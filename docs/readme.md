# TG Parser — Алготрейдинговый бот на Bybit

Автоматизированный торговый бот: парсит сигналы из Telegram-каналов, исполняет сделки на бирже Bybit по стратегии динамической DCA-сетки, управляет позициями и уведомляет о результатах.

---

## Модули

### `main.py` — Оркестратор
Точка входа. Класс `TradingBot` инициализирует все подсистемы и запускает их параллельно через `asyncio.gather()`.

**Задачи:**
- Авторизация в Telegram через Telethon
- Подписка на события нового сообщения в целевом канале
- Producer-Consumer паттерн через `asyncio.Queue`: принятый сигнал помещается в очередь, воркер извлекает и передаёт на биржу
- Запуск параллельных задач: монитор биржи, поллинг команд, веб-сервер

### `parser.py` — Парсер сигналов
Извлекает торговые данные из текста сообщения регулярными выражениями.

**Возвращает словарь:**
```python
{
    "coin": "BTCUSDT",
    "signal_type": "OPEN",       # OPEN / CLOSE
    "direction": "LONG",
    "price": 95000.0,            # цена входа
    "target_price": 96500.0,     # тейк-профит
    "received_at": "2026-04-20T14:30:00"
}
```

**Особенности:**
- Поддержка кириллических тикеров (BTCUSDT → перевод латиница)
- Фильтрация спам-сообщений и рекламы
- Логирование всех принятых сигналов в `logs/signals_raw.log`

### `bybit_exchange.py` — Торговый движок
Класс `BybitExchange`. Центральный модуль: открывает позиции, управляет ордерами, обрабатывает исполнения.

**Логика открытия позиции (`_handle_open_signal`):**
1. Проверить: разрешены ли новые входы, не превышен ли лимит активных сделок
2. Получить текущую рыночную цену
3. Рассчитать объём ордера: `deposit × dca_volume_0% × leverage / price`
4. Выставить маркет-ордер Buy
5. Получить реальную цену и объём исполнения
6. Сохранить сделку в БД
7. Выставить лимитный TP-ордер (Sell, reduce_only)
8. Выставить лимитный DCA-1 ордер (если усреднения разрешены)
9. Отправить уведомление в Telegram

**Логика усреднения (`_process_dca_execution`):**
1. DCA-ордер исполнился → получить данные исполнения
2. Обновить сделку в БД (новый шаг, средняя цена, суммарный объём)
3. Отменить старый TP-ордер
4. Выставить новый TP по обновлённой средней цене
5. Если шаг < 3 — выставить следующий DCA-ордер
6. Отправить уведомление

**Логика закрытия по TP (`_process_tp_fill`):**
1. TP-ордер исполнился
2. Рассчитать итоговый PnL (с учётом комиссий и фандинга)
3. Закрыть сделку в БД
4. Отправить уведомление с результатом

### `database.py` — Слой данных
Четыре независимых класса, каждый работает со своей SQLite-базой.

| Класс | Файл БД | Назначение |
|---|---|---|
| `Database` | `db/signals.db` | Хранение всех принятых сигналов |
| `TradesDatabase` | `db/trades.db` | Активные и закрытые позиции |
| `SettingsDatabase` | `db/settings.db` | Параметры бота (DCA, TP, лимиты) |
| `CoinsDatabase` | `db/coins.db` | Вайтлист монет и алиасы |

### `notifier.py` — Telegram-уведомления
Класс `Notifier`. Отправляет уведомления и принимает команды через Telegram Bot API (Long Polling).

**Уведомления:**
- `🟢 ВХОД: {coin}` — открытие позиции (цена, объём USDT, TP, план DCA)
- `⚖️ DCA #{n}: {coin}` — усреднение (объём USDT, средняя цена, новый TP)
- `✅ TP: {coin}` — закрытие по тейк-профиту (цена, Net PNL)

**Команды бота:**

| Команда | Действие |
|---|---|
| `/status` | Статус подключений, баланс, PNL, активные позиции |
| `/balance` | Баланс на Bybit и зафиксированный PNL |
| `/stop` | Запретить новые входы |
| `/go` | Разрешить новые входы |
| `/help` | Список команд |

### `web_server.py` — Веб-дашборд (FastAPI)
REST API + HTML-интерфейс на порту `8000`.

**Эндпоинты:**

| Маршрут | Метод | Описание |
|---|---|---|
| `/` | GET | Дашборд (HTML) |
| `/settings` | GET/POST | Просмотр и изменение настроек |
| `/api/data` | GET | Live данные: баланс, позиции, сигналы |
| `/api/history` | GET | История закрытых сделок + статистика PNL |
| `/api/coins` | GET/POST | Управление вайтлистом монет |
| `/api/coins/{coin}` | DELETE/PUT | Удаление/активация монеты |
| `/api/positions/{coin}/close` | POST | Принудительное закрытие позиции |

### `config.py` — Конфигурация
Загружает `.env` из `config/.env` (или корневой `.env`). Предоставляет типизированные константы.

### `logger.py` — Логирование
- `bot_logger` → `logs/bot_system.log` (ротация 5 МБ × 5 файлов)
- `raw_logger` → `logs/signals_raw.log` (ротация 10 МБ × 3 файла)
- Все метки времени в МСК (GMT+3)

## Схема баз данных

### trades (db/trades.db)
```
id          INTEGER PK
coin        TEXT            -- тикер: BTCUSDT
step        INTEGER         -- шаг DCA: 0=вход, 1-3=усреднения
status      TEXT            -- TRADING | closed | STUCK
buy_p/a     REAL            -- цена/объём первого входа
dca1_p/a    REAL            -- цена/объём DCA-1
dca2_p/a    REAL            -- цена/объём DCA-2
dca3_p/a    REAL            -- цена/объём DCA-3
avg_p       REAL            -- средняя цена позиции
total_inv   REAL            -- суммарный объём в USDT
leverage    INTEGER
open_fee    REAL            -- комиссия входа
funding_fee REAL            -- фандинг
close_fee   REAL            -- комиссия выхода
net_pnl     REAL            -- чистый PnL
tp_order_id TEXT            -- ID TP-ордера на бирже
dca_order_id TEXT           -- ID активного DCA-ордера
created_at  TEXT
exit_p      REAL
pnl/pnl_p   REAL
```


## Торговая стратегия (DCA Grid)

```
Цена входа: 100 USDT  (объём: 2% от депо × плечо)
     │
     ▼ −3.5%
DCA-1: 96.5 USDT      (объём: 4% от депо × плечо)
     │
     ▼ −6.5% от DCA-1
DCA-2: 90.2 USDT      (объём: 8% от депо × плечо)
     │
     ▼ −14.5% от DCA-2
DCA-3: 77.1 USDT      (объём: 16% от депо × плечо)
     │
     ▲ +1.5% от средней цены
TP:  средняя_цена × 1.015
```

На каждом шаге:
- Старый TP-ордер отменяется
- Новый TP рассчитывается от обновлённой средней цены
- Следующий DCA-ордер выставляется автоматически (если разрешено)

## Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone <repo>
cd tg_parser

# 2. Создать виртуальное окружение
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # Linux/Mac

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать конфиг
cp config/.env.example config/.env
# Заполнить config/.env

# 5. Авторизоваться в Telegram (первый раз)
python utils/auth_me.py

# 6. Наполнить базу монет
python utils/fill_coins.py
```

### Способы запуска

| Способ | Команда / Действие | Примечание |
|---|---|---|
| **GUI (рекомендуется)** | Двойной клик на `start.bat` | Нет терминала, трей, лог, авто-рестарт |
| Ярлык на рабочем столе | `TG Parser.lnk` | Создаётся один раз, см. ниже |
| Терминал с venv | `python app_gui.py` | Для разработки |
| Только бот (без GUI) | `python main.py` | Как раньше, через терминал |

**Дашборд:** http://127.0.0.1:8000

### Перенос на новый Windows-ПК

Если проект переносится на другой ПК:

1. Скопировать всю папку проекта
2. Запустить `install_windows.bat`
3. Заполнить `config/.env` или перенести готовый файл со старого ПК
4. При необходимости перенести `config/*.session` и папку `db/`
5. Запустить `start.bat`

## Сборка standalone .exe (PyInstaller)

Позволяет запустить приложение на ПК без установки Python и зависимостей.

```bash
# 1. Установить PyInstaller (один раз)
pip install pyinstaller

# 2. Собрать
pyinstaller tg_parser.spec

# Результат: dist/TgParserBot.exe
```

**Что нужно положить рядом с .exe перед запуском:**
```
dist/
├── TgParserBot.exe
├── config/
│   └── .env              ← конфигурация (не упакована в exe)
└── db/                   ← базы данных (создаются автоматически)
```

> `templates/` и `icon.png` упакованы внутрь `.exe` через `tg_parser.spec`.  
> При обновлении кода — пересобрать: `pyinstaller tg_parser.spec`.  
> При добавлении новых зависимостей — добавить их в `hiddenimports` в `tg_parser.spec`.
